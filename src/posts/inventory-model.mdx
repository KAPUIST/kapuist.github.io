## 하나의 아이템은 누구의 것일까?

플레이어 두 명이 같은 종류의 체력 물약을 가지고 있다고 생각해 봅니다. 물약의 이름은 같지만, 각 플레이어가 가진 **수량**은 다릅니다.

아이템의 설명과 플레이어의 보유 상태를 나누면, 같은 설명을 여러 번 저장하지 않아도 됩니다.

| 테이블 | 저장하는 정보 | 예시 |
| --- | --- | --- |
| `players` | 플레이어 | 플레이어 ID, 이름 |
| `items` | 아이템의 정의 | 아이템 ID, 이름 |
| `inventory` | 플레이어별 보유 상태 | 플레이어 ID, 아이템 ID, 수량 |

## 같은 아이템을 중복 등록하지 않으려면

아래 예시는 `players(id)`와 `items(id)`가 이미 있다고 가정합니다.

```sql
CREATE TABLE inventory (
  player_id bigint REFERENCES players(id),
  item_id bigint REFERENCES items(id),
  quantity integer NOT NULL CHECK (quantity >= 0),
  PRIMARY KEY (player_id, item_id)
);
```

두 ID를 묶은 기본 키는 같은 플레이어와 아이템 조합이 두 행에 들어가는 것을 막습니다. `CHECK`는 수량이 음수가 되는 것을 막습니다.

## 이 모델로 다 표현할 수 있을까?

같은 검이라도 강화 수치나 내구도가 다르면 각각 구분해야 합니다. 그런 게임에서는 아이템 종류와 **개별 아이템 인스턴스**를 나눠 생각해야 합니다.

- 쌓을 수 있는 물약과 개별 장비를 어떻게 구분할까?
- 거래 도중 아이템이 중복 전달되지 않으려면 무엇이 필요할까?
- 두 요청이 동시에 수량을 바꾸면 어떤 일이 생길까?
