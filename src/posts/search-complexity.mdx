## 원하는 아이템을 어떻게 찾을까?

아이템 ID가 오름차순으로 정렬된 목록을 떠올려 봅니다. 처음부터 하나씩 살펴볼 수도 있고, 가운데를 확인한 뒤 탐색 범위를 절반으로 줄일 수도 있습니다.

**이진 탐색에는 정렬된 데이터가 필요합니다.** 정렬되지 않은 인벤토리에 그대로 적용할 수는 없습니다.

## 그래프가 보여 주는 것

순차 탐색은 최악의 경우 모든 아이템을 확인합니다. 아이템이 `n`개면 비교 횟수는 최대 `n`회입니다.

중간 원소를 비교하는 일반적인 이진 탐색은 범위를 반복해서 절반으로 줄입니다. 이 예제는 `n ≥ 1`에서 최대 비교 횟수를 `⌊log₂(n)⌋ + 1`로 계산합니다.

```ts
function binarySearch(ids: number[], target: number) {
  let left = 0
  let right = ids.length - 1

  while (left <= right) {
    const mid = Math.floor((left + right) / 2)
    if (ids[mid] === target) return mid
    if (ids[mid] < target) left = mid + 1
    else right = mid - 1
  }

  return -1
}
```

## 비교 횟수가 적으면 무조건 빠를까?

실행 시간에는 메모리 접근, 데이터 크기, 정렬 비용 등도 영향을 줍니다. 이 그래프는 **증가하는 방식의 차이**를 이해하기 위한 도구입니다.

데이터베이스의 인덱스도 이 예제와 동일한 알고리즘이라고 단정하면 안 됩니다. 자료구조와 실행 계획을 따로 살펴봐야 합니다.
